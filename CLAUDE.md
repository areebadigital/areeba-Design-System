# areeba Asterisk 4

areeba's design system, fourth generation: the source of truth for areeba's design language (web and React Native apps, SaaS, Kotlin card machines). Logo for the system itself: `assets/Logos/asterisk-*.svg`; product screens keep the areeba wordmark. Published live at https://claude.ai/artifact/XvWoiWjkXwRi4FxLZeE15T (Design System artifact).

- `tokens.json` is the only place values live. After changing it run `python3 scripts/build-tokens.py` to regenerate `tokens.css`.
- Component code lives in `src/`: one folder per component (`src/components/<Name>/<Name>.js` and `<Name>.css`), shared helpers and hooks in `src/core/`, page-level CSS in `src/styles/`, public exports in `src/index.js`, CSS order in `src/css-order.json`. Plain JS with `React.createElement` (no JSX), CSS that reads only CSS variables.
- `npm run build` (esbuild) generates `components/bundle.js` (React 18 global script, `window.Areeba`) and `components/bundle.css`; never edit those by hand. `npm run check` (run in CI) fails if they are out of date or any source file is over 1000 lines; keep components under 300 lines by moving shared logic into `src/core/`. `components/index.d.ts` holds the types.
- Packages (`packages/`, npm workspaces, scope `@areebadigital` on GitHub Packages): `asterisk-tokens`, `asterisk-react`, `asterisk-native`, `asterisk-cli`, `asterisk-lint`, and Kotlin `asterisk-kotlin` (Gradle, `com.areeba.asterisk:asterisk-tokens`). Platform tokens (`packages/asterisk-tokens/dist`, `AsteriskTokens.kt`) come from `tokens.json` via `node scripts/build-platform-tokens.mjs`; React Native icons via `node scripts/build-native-icons.mjs`; both are committed and checked in CI with `--check`. `npm run build:packages` makes the rest (react `dist/`, fonts, CLI blocks, `components.json`, `llms.txt`), which is not committed. Releases go through Changesets (`npm run changeset`); all packages share one version.
- React Native (`packages/asterisk-native/src`) mirrors the web components' names, props and analytics events with RN primitives, `Animated` and token durations, `useAsterisk()` for theme, direction and fonts. Keep `src/index.d.ts` in step. `npm run test:native` renders `demo/App.js` with react-native-web and checks errors, overflow, RTL and analytics; add new components to the demo.
- Kotlin Compose (`packages/asterisk-kotlin/compose`, Kotlin Multiplatform: Android + JVM) holds the card-machine components and the customer display (`CustomerDisplay`, `CustomerPresentation` in `androidMain`). Same rules: tokens only via `Asterisk.colors` and `textStyle()`, motion via `theme.tween()`/`Modifier.enter()`, `Analytics` props and `rememberTrack`, touch targets at least 48dp, amounts and ids left to right. `./gradlew :compose:jvmTest` renders every screen in light, dark and Arabic to `compose/build/shots`; look at them after a change. Icons come from `scripts/build-native-icons.mjs`.
- Agent docs: `docs/agents/AGENTS.md` and `docs/agents/rules.md` are the source for the packages' `AGENTS.md` and `llms.txt`; update them when a rule changes.
- Each component has `components/<Name>/README.md` (guidelines) and `preview.html` (line 1 is a `@dsCard` marker the artifact reads).
- `components/Cover/preview.html` is the artifact's cover, not a component.
- Every change here should also be published to the artifact above so both stay in sync.
- Figma library: areeba Design System 4.0, https://www.figma.com/design/HUoG7rGPlAR8cQAaV4fswZ (variables mirror `tokens.json`; components mirror `bundle.js`). Keep it in step when tokens or components change.
- `figma/*.figma.ts` are Code Connect templates (parserless `figma.code`, one per component and exported icon). Update a template when its component's Figma properties or code props change. Publishing needs an Organization/Enterprise Figma plan.
- Colours must keep text at 4.5:1 in light and dark; chart-1..4 stay in fixed order.
- Arabic is first-class: every component must work with `dir="rtl"`. Use logical CSS (start/end, `inset-inline`, `margin-inline`), never left/right; keep amounts, IBANs and card numbers left-to-right (isolate with `dir="ltr"` or `ltr()`); give built-in words an Arabic entry in `UI_TEXT`. In Storybook's RTL mode stories show Arabic: add every new story string to `stories/i18n.js`, and check the story with the Direction switch.
- Motion uses only the motion tokens (`--duration-instant|fast|base|slow`, `--ease-standard|enter|exit`, `--motion-distance`) and the shared keyframes in `src/styles/motion.css`; `npm run check` fails on raw `ms` or `cubic-bezier()` in component CSS. Animate what enters, not what leaves; move only opacity, transform, colours and borders. Reduced motion is handled by the tokens (durations become 0ms).
- Analytics: every interactive component calls `useTrack` (`src/core/analytics.js`) and accepts `analyticsId`/`analyticsData`; `rest()` keeps them off the DOM and `analyticsAttrs()` adds `data-analytics-id`. Events are `asterisk.<component>.<action>`, listed in `ANALYTICS_EVENTS` and the Analytics guide. Never put what people type or see (amounts, IBANs, card numbers, names, codes, messages, file names) in an event; `tests/visual/analytics.spec.mjs` checks this.
- Never use native browser controls (no native `<select>`, date inputs or pickers): draw every control in `bundle.js` and follow its WAI-ARIA pattern. Text entry keeps a real `<input>`, the only exception. Form values from custom controls travel in `<input type="hidden">`.
- Actions and selection use `brand` (Crimson Deep). Signal Red (`accent`) is only the logo and large headline highlights, never buttons or status: in money products bright red reads as an error.
- Screenshot tests (`tests/visual/`, `npm run test:visual` after `npm run build-storybook`) cover every story in light, dark and RTL, plus axe, errors, overflow and English left in RTL. References are generated only in CI (label a PR `update-screenshots`, or run the "Screenshot tests" workflow by hand with "Update the reference screenshots"), never committed from a local machine. Keep the workflow's Playwright image tag and `@playwright/test` on the same version.
- Blocks (`blocks/`) are copyable whole screens in JSX built only from `window.Areeba` components and tokens, with an English and Arabic `COPY` object picked from `<html lang>`. Each has a story in `stories/blocks/` that shows its own file as the source. A block never adds styles of its own beyond the layout classes (`ar-screen-*` for mobile screens, `ar-app-*` for SaaS pages: `ar-app-split`, `ar-app-col`, `ar-app-narrow`, `ar-app-form`, `ar-app-auth-*`); if it needs something new, build it as a component first.
- Storybook (`stories/`, `npm run storybook`) documents everything. When you add or change a component, token family or asset, update its story or foundation page too; component docs come from each `README.md`, so keep those current.
